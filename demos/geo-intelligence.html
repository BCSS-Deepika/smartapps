Why it exists

Every department already has the geography. It is in forty different files.

Scattered GIS assets

Boundaries, operational layers, road shapefiles and survey sheets each sit in their own folder and their own format, converted by hand whenever someone needs a map.

ONE CATALOG · ONE MAP · ONE COMPOSITION

Road networks too big for a browser

A single state's road network can exceed 150,000 segments. Sent as one file it stalls the browser, so planning a route on the real network is not practical.

SERVED BY MAP AREA · OR AS TILES

Field teams need offline

A district team going out needs a printed sheet and something a handheld can open — not a web page they cannot reach once they leave coverage.

Platform Architecture

Mostly a browser. A database only when it has to be.

Read it as four bands. Geography is prepared offline and served as files. The operator works entirely in the browser. A small service exists only for road data too big to ship as a file. Basemaps and a routing fallback come from outside. Click any box for what it takes in, what it produces, and how it fails.

Deploying in a new state

The platform does not change. Six things do.

Everything that makes a deployment local is configuration and data loading, not a rebuild. That is what makes the same platform work for a police department, a transport authority or a disaster management agency.

CONFIGURED PER STATE

What changes

Six items, loaded or set at deployment. None of them require a code change.

Administrative boundariesThe state's own authoritative state, district, sub-district and village layers replace the base set.
Jurisdiction hierarchy and namesMandal, taluk, tehsil, block, circle — the levels and their labels are set to match how the state is actually administered.
Road networkThe state's network is loaded into the spatial database and served by map area, so size stops being a limit.
Operational layersThe department's own enforcement, asset or incident layers are converted and added to the catalog.
Identity and rolesConnected to the department's existing identity provider, with the role-to-workspace matrix set to its own rank structure.
LanguageInterface labels and map annotation in the languages the department works in.
THE SAME EVERYWHERE

What does not change

The engine, the model and the outputs are identical across deployments — which is why a second state costs a fraction of the first.

Map engine and drillOne shared map behind every workspace, with the same nation-to-village traversal.
Catalog and composition modelTick layers, save to a destination, work from the saved composition. Identical everywhere.
Routing and corridor analysisMulti-point routing over whatever network is loaded, with a public fallback where permitted.
Field productsAtlas sheets, KMZ packaging and raster overlays behave the same against any geography.
Serving strategyFiles first, spatial database for anything too large — the same pattern regardless of state size.
Reporting and audit modelThe same action trail, the same exports, the same governance screens.
